FUTURE HARDWARE EXTENSION

ESP32 integration.

A planned pathway from software Braille patterns to a physical tactile display.

ESP32BLE BOARD
Bluetooth · not connected

Bring Braille to touch.

Connect to an ESP32 BLE UART device, then transmit a compact JSON payload containing the text and six-dot patterns.

Bluetooth requires Chrome/Edge on a supported device and an ESP32 running the matching BLE UART firmware.

Data communication payloadJSON · UTF-8
Convert text first to preview the payload.

Payload fields: protocol, text, Unicode Braille, and dot arrays. Send is enabled only after a BLE connection.

Optional Braille API

Use a compatible API endpoint if your team deploys one. Local converter remains the fallback.

API is optional; local Braille conversion works offline.

Communication flow

Text input → Braille encoder → JSON packet → Web Bluetooth (BLE GATT) → ESP32 BLE UART service → display controller → six-dot actuator cell. This website sends data; the ESP32 firmware and physical display must be built separately.

Problem statement

Digital text on phones and websites can be difficult for blind users to access independently. This project proposes a browser-based tool that converts typed or dictated English text into Braille representations and audio, with a future pathway to tactile hardware.

Objectives

  • Make text entry possible through keyboard, paste, and speech recognition.
  • Convert supported English text into Grade 1 Braille patterns.
  • Offer visual six-dot and ASCII learning representations.
  • Provide audio reading and keyboard-accessible controls.
  • Prepare a future ESP32 hardware integration pathway.

Current scope

This is a software prototype. The visual simulator and browser audio are implemented; physical Braille hardware and real ESP32 communication are future work.
